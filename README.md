# Kirin Drop experience — public development source

This package contains the two public measurement wrappers, their pinned public
dependencies, the development experience frontend and reproducible build recipes.
It also contains the bounded bilingual website candidate in `dev/drop-public`:
original WAV measurement at 44.1/48/96 kHz, no longer than 90 seconds and 32 MiB.
Its active graph excludes the historical beat/chord estimator. The song-sheet
example is explanatory data, not analysis of the listener's uploaded WAV.
Daisuke approved publishing this limited Drop code under GPLv3 on 2026-10-09.
The combined experience is GPL-3.0-only; see `LICENSE` and `NOTICES.md` for the
MIT wrapper and original third-party licences.

**This is development source, not the released Kirin OS application or a completed
production website demo.** The source publication does not waive measurement,
browser or production deployment acceptance. No application release is announced.

Kirin OS's private engine, models, licence-handling code, user audio and studio
data are not included. Owner-approved presentation assets are included only at
the pinned UI boundary in `dev/drop-preview/kirin-ui/source.json`; this is not
the complete application. The full HP repository, fonts, photography,
commerce endpoints and credentials are outside this package.

## Build the public cores

Use Rust 1.94.1 and the `wasm32-unknown-unknown` target. The `.cargo/config.toml`
in this candidate selects the included `third-party` dependency source. No private
Kirin checkout or API is needed. With the toolchain installed:

```sh
node scripts/build-drop-cores.mjs
```

The recipe uses `--offline --locked`. It builds both Wasm cores and the two native
`reference` executables. `dev/drop-preview/core-build.json` records the generated
hashes. Recipe v2 remaps crate and dependency source paths to stable identities.
Inside a candidate package, the build compares both Wasm binaries with
`source-manifest.json`'s original binary receipt and fails on any byte/size or
compiler mismatch. A successful numerical comparison alone is not reproduction.

The C ABI is in each wrapper's `src/lib.rs`; the JS caller is
`dev/drop-preview/wasm-core.mjs`. `measure.mjs` parses the original WAV;
`analyze.mjs` runs the capabilities independently; `worker.mjs` isolates the work.
The browser only fetches static cores. It does not send audio to a server.

## Verify calculations

```sh
node scripts/verify-drop-common-core.mjs
node scripts/verify-drop-psycho-reference.mjs
node scripts/verify-drop-dsp.mjs --common
```

The last command requires an already installed FFmpeg. These are bounded synthetic
and saved public-reference tests, not product-binary, real-music, browser, ISO or
EBU certification. The saved MoSQITo reference is not regenerated by these tests.
See `NOTICES.md`, the included reference provenance and the build receipt.
`loudness.mjs` is included only because the historical/FFmpeg diagnostic runner
imports it; the active experience uses the two public Wasm cores, never this old
JavaScript estimator or a fallback to it.

The HTML, CSS and frontend modules are included for review of the integration.
The instrument JSX and display-only models are a restricted, owner-approved
snapshot, with exact provenance in `kirin-ui/instruments/source.json`. React,
React DOM, Scheduler and esbuild retain their MIT notices in `third-party-js`.
On macOS with the same Node architecture (currently x64), Node 24 and the included pinned build dependencies can
reproduce the instrument bundle offline, without a private Kirin OS checkout:

```sh
node scripts/build-drop-instruments.mjs --rebuild --dependency-root third-party-js
```

`--rebuild` compares the generated bundle to the candidate hash and fails on a
mismatch; it never substitutes a changed bundle or renews the original receipt.
The Kimera font is not bundled; it remains a separately licensed website asset.
Do not run this source package as an Internet-facing upload service.

## Scope and remaining acceptance

The source contains the complete selected frontend module graph, instrument JSX,
display-only models, two wrappers, public calculations and fixed dependencies.
`PUBLICATION.json` records the owner approval and exclusions. No licence is being
changed for the rest of the HP or Kirin OS. Photography and the Kimera font are
not distributed here. CSS may refer to separately licensed website assets; do not
infer redistribution rights for those assets from this code licence.

Numerical verification uses bounded synthetic signals and saved public references.
This is not product-binary parity, real-music acceptance, or ISO/EBU certification.
Known remaining checks include the 8 kHz abrupt-tail True Peak reference difference
(about 0.17 dB), a 192 kHz approximate loudness criterion (about 0.027 LU), beat/chord
candidate quality on real music, Safari/iPhone, reduced-motion and production
integration. Beat/chord outputs remain uncalibrated candidates, never confirmed
scores or an actual STAGE/QR connection. Private OS calculations are not supplied.
The bounded website candidate rejects those unaccepted 8/192 kHz inputs; it does
not fix or silently waive the historical criteria. Manual motion suppression and
Chrome desktop/mobile-size checks belong to the HP acceptance record, not an
assurance for Safari or physical iPhones. `scripts/build-drop-public.mjs` assembles
only the reviewed static graph; the separately licensed website fonts must be
supplied by the HP checkout, and are deliberately absent from this source package.
